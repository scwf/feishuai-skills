# X 每日推文智能分析师

## 使用场景

用户想要对 x-scraper 已生成的 X 推文 batch 目录进行深度分析。该技能默认从 `~/data/x-daily/latest` 解析最新 batch；如果该目录下 `meta.json` 文件中的 `batch_dir` 不存在，再要求用户提供一个真实 batch 目录。该技能不重新抓取 X，只读取已有批量数据并输出分析结果。

典型触发语：
- “分析今天/最新的 X 日报”
- “看看今天 X 上 AI/数据/开发工具圈有什么重要动态”
- “分析 `model_vendor` / `devtools_agent` / `ai_infra` 这个类别”
- “从产品经理/技术负责人/超级个体视角解读这批 X 推文”
- “分析这个 `x-posts-batch-*` 目录里的推文情报”

## 数据源

- **默认指针目录**：`~/data/x-daily/latest/meta.json` 可包含 `batch_dir`，指向最新 x-scraper batch
- **Batch 目录**：x-scraper 批量抓取生成的真实目录，例如 `/path/to/x-posts-batch-YYYYMMDD-HHMMSS`
- **类别索引**：`{batch_dir}/batch_category_index.json` 定义类别与对应账号 JSON 文件映射，类别列表以文件内容为准
- **原始推文**：`{batch_dir}/raw/*.json` ，每个账号一个 JSON 文件，包含结构化推文数据

`latest` 只是指针，不是独立数据源。解析出真实 batch 目录后，后续流程始终按真实 batch 目录读取。

## 执行流程

### Step 1: 确认批次

1. 优先读取 `~/data/x-daily/latest/meta.json` 的 `batch_dir` 得到真实 batch 目录；如果不存在或无效，再让用户提供一个 x-scraper batch 目录
2. 提取批次日期，优先使用 `meta.json.date`，其次从 batch 目录名或 `summary.json` 中读取
3. 告知用户：**"将读取 X batch（{date}）：{batch_dir}，共 N 个类别可供分析。"**

### Step 2: 选择分析模式

先判断用户请求是否已经指定类别和视角。

**默认规则（重要）**：

必须指定一个类别后才能分析；不做全类别综合分析。

如果用户只说“分析今天的推文”“分析最新 X 日报”“看看今天有什么重要动态”“今天 X 上有什么值得关注”等宽泛请求，先读取 `batch_category_index.json` 的类别列表，然后请用户确认类别和视角。

只要类别或视角任一不明确，都要先让用户确认选择：

1. 类别缺失、类别名称不在 `batch_category_index.json` 中，或用户只描述了宽泛主题但无法映射到唯一类别
2. 视角缺失，或用户表述无法明确映射到 **Data & AI 产品经理**、**技术负责人**、**超级个体** 之一
3. 用户同时给出多个类别或多个视角，但没有说明优先级

可选类别：从 `batch_category_index.json` 的 `categories` 键中动态提取列表。
例如：`ai_infra`, `model_vendor`, `devtools_agent`, `data_infra`, `cloud_platform`, `ai_researcher`, `research_org`, `ai_media_community`, `open_community`, `super_agent`

可选视角：
- **Data & AI 产品经理**：关注市场动态、竞品信号、产品化路径、用户价值
- **技术负责人**：关注架构影响、技术上下游、落地成本、工程可行性
- **超级个体**：关注个人效率工具、可复用工作流、知识更新、个人竞争力

如果用户已经提供类别和视角，直接进入 Step 3。

### Step 3: 读取与格式化数据

运行辅助脚本提取指定类别的数据：

```bash
python3 "{SKILL_ROOT}/scripts/extract_posts.py" --category <CATEGORY>
```

脚本会：
- 读取指定类别下所有账号的 JSON 文件
- 对每条推文提取精简格式：
  - 作者信息（`username` / `display_name`）
  - 发布时间（`created_at`）
  - **内容优先级**：如果是 RT，优先用 `retweeted_original_text` 获取完整原始文本，避免 `original_text` 的截断
  - 互动数据（浏览量、点赞、转发）作为参考信号
  - 外链与原文 URL
- 输出为易于 LLM 处理的纯文本格式

### Step 4: 信息补全（保守触发）

在分析前，对以下情况保守触发搜索补全：
- 推文内容少于 20 个字，且无链接、无图片说明
- 是一条 announcement 式推文，但缺乏上下文（如 "We're excited to announce X" 但没有解释 X 是什么）
- 包含一个新产品/公司/术语名称，但整个 batch 里只有这一条提及该主题，无法从其他推文中获取背景

搜索补全时：用 `search` 或 `browser` 查找该主题的官方博客、新闻稿、或可信来源，用 1-2 句话补充背景到分析中。

**不触发搜索的情况**：
- 推文本身已经很完整（有详细解释、数据、链接）
- 同一主题在 batch 内有多条推文互相补充，可以自我推断背景

### Step 5: LLM 深度分析

通读全量格式化后的推文内容，提炼该类别在该批次中的 **Top 5 核心主题**。

**分析框架**（固定两大维度）：

对每个主题：
1. **📌 事实**：发生了什么事？（已补全背景后的完整事实描述）
   - 如果涉及产品发布、技术更新、数据成果，具体说明是什么
   - 如果是观点、论述、预测，概括核心论点
2. **💡 意义与价值**：从选定视角看，这件事的价值和影响是什么？
   - 对行业/竞品格局的影响
   - 对目标受众（产品经理/技术负责人/超级个体）的启示

**聚合原则**：
- 不是按推文逐条评论，而是跨账号、跨推文的主题聚合
- 如果多条推文讨论同一事件，合并为一个主题，使用最丰富的那条作为主干
- 如果某个主题只有一条推文但信息量很大（如官方发布、重要数据），也可单独成为一个 Top 5 主题

### Step 6: 输出格式

**微信竖屏友好格式**：
- 中文为主，关键产品名/技术名保留英文
- 绝对不使用 Markdown 表格
- 不使用标题级别（`#` / `##`），只用简单文本标题
- 主题之间用 `────────────` 分隔
- 可使用 `1️⃣ 2️⃣ 3️⃣` 作为序号
- 每个主题应是有信息密度的短分析，不要为了简短而省略关键背景、证据链或判断逻辑
- `事实` 和 `意义` 默认各写 1 个短段落；复杂主题可扩展为 2 个短段落，但避免流水账

**输出示例**：

```
📊 X 情报 · {category} · {perspective}视角 ({date})

1️⃣ {topic_title}

📌 事实：
{用一个信息完整的短段落说明发生了什么、涉及谁、关键变化/数据/发布内容是什么；如有必要，补充来源或上下文}

💡 意义：
{从选定视角解释为什么重要、会影响什么决策/产品/技术路线/个人工作流；给出明确判断，而不是泛泛评价}

────────────

2️⃣ {topic_title}
...
```

**注意**：
- 如果某个主题涉及多条推文，可在"事实"末尾简要提及涉及的核心账号
- 如果分析过程中触发了搜索补全，需在输出中标注信息来源（如"补充自 XX 官方博客"）
- 如果该类别在本批次中的推文量过少（少于 5 条有效推文），实事求是地说明情况，而不是硬挑 5 个主题

## 边界规则

- **不做**：不重新抓取 X 数据，只分析已有的批量数据
- **不做**：不生成任何文件保存到磁盘，只输出分析结果给用户
- **不做**：不对推文做情感分析、辈论评级、或个人攻击
- **做**：主动补全信息缺失，确保"事实"维度是准确的
- **做**：从选定视角出发进行有针对性的价值判断

## 命令

```bash
python3 "{SKILL_ROOT}/scripts/extract_posts.py" --category model_vendor
```

如果默认 `~/data/x-daily/latest` 不存在，或用户明确指定某个 batch：

```bash
python3 "{SKILL_ROOT}/scripts/extract_posts.py" --batch-dir /path/to/x-posts-batch-YYYYMMDD-HHMMSS --category model_vendor
```
