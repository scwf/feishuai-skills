# Research Lens

Use this lens before writing any infographic prompt.

## Data & AI Product Manager Lens

Extract:

- User/job scenario: who uses it, for what job, in what workflow.
- Product positioning: model, platform, tool, runtime, application, ecosystem, or infrastructure.
- Differentiation: what makes it not “another AI product”.
- Adoption trigger: why users or enterprises would switch, pay, deploy, or standardize on it.
- Value metric: speed, cost, reliability, autonomy, quality, collaboration, governance, or time-to-production.
- Product packaging: API, SDK, app, CLI, managed service, marketplace, plugin, skill, connector, or agent.
- Strategic implication: what this changes in the market, stack, workflow, or vendor relationship.

Useful questions:

- What is the product really selling: capability, workflow, infrastructure, operational promise, or ecosystem position?
- What user pain is being converted into a product abstraction?
- Which part is a feature, and which part is a platform strategy?

## Technical Lead Lens

Extract:

- Capability claims: coding, tool use, long context, multimodal, search, planning, memory, parallel agents, UI generation.
- Engineering proof: benchmark, latency, throughput, cost, reliability, success rate, failure recovery, security boundary.
- Runtime behavior: session, state, tool loop, sandbox, event log, context management, recovery, permission, orchestration.
- Integration surface: APIs, SDKs, CLI, MCP, plugins, connectors, files, browser, terminal, IDE, cloud service.
- Production concern: observability, permissioning, isolation, auditability, rollback, scaling, SLA, deployment model.

Useful questions:

- What technical mechanism makes the capability credible?
- Is the claim model-native, runtime-enabled, or system-engineering-enabled?
- What would a technical leader need to believe before adopting it?

## Technical Architect Lens

Extract:

- System structure: layers, components, control plane, data plane, tool plane, memory plane, execution plane.
- Data/control flow: what calls what, where state lives, how events flow, where permissions are enforced.
- Boundary design: model vs runtime, app vs platform, session vs context, sandbox vs vault, orchestration vs execution.
- Abstraction shift: from container to recoverable runtime, from model to agent system, from tools to ecosystem, from benchmark to workflow.
- Architectural tradeoff: coupling vs decoupling, hosted vs self-built, closed vs open ecosystem, single-agent vs multi-agent.

Useful questions:

- What is the best main diagram: stack, flow, loop, flywheel, timeline, old-vs-new, or ecosystem map?
- Where is the architectural “aha”?
- Which boundary or abstraction should be visually emphasized?

## Required Extraction Output

Before making the prompt, produce or internally prepare:

- Topic
- Target reader
- Source mode: Minimal Topic Input or Reference-Locked Input
- Core facts
- Core mechanism
- Common capabilities
- Unique insight
- Evidence/data
- Visual metaphor or main diagram
- Bottom insight sentence
