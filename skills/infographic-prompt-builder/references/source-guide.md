# 信息图制作指导手册

> 适用范围：产品战略信息图、技术架构信息图、竞品分析信息图、行业洞察信息图、单产品深描卡、汇报型高管页  
> 目标：把“有价值的观点”翻译成“高效、清晰、有高级感的图形表达”

---

## 一、核心原则

信息图不是把文字排版得更漂亮。  
信息图的本质，是把观点翻译成图形语言。

做一张好信息图，重点不在于“塞了多少信息”，而在于：

- 这页最想让人一眼看懂什么
- 哪些信息必须变成图
- 哪些信息只能做注释
- 哪一句话是最终要留下来的判断

### 一句话方法论

**主图讲结构，辅图讲差异，小图讲证据，底部一句话收束判断。**

---

## 二、第一步：先定这页只讲一个主判断

一页信息图，最怕同时讲三件事。

常见问题是把这些东西混在一页里：

- 它是什么
- 它和谁是什么关系
- 它哪里独特
- 它为什么重要
- 它带来什么价值

这些都重要，但一页里只能有一个是主轴。

### 使用方法

开始做图前，先回答一句话：

**“如果领导只看 5 秒，这页最应该留下什么结论？”**

例如：

- 产品关系图：  
  **Anthropic 的产品不是并列清单，而是分层协同体系。**

- 单产品深描卡：  
  **Claude Managed Agents 的独特性不只是平台能力，而是三层解耦的 Agent runtime。**

- 战略飞轮图：  
  **Anthropic 的产品协同逻辑是：一方应用验证 → 平台能力沉淀 → 生态扩散 → 再反哺产品。**

这句话确定后，再去决定版式和图形，否则很容易画成“漂亮但不聚焦”。

---

## 三、第二步：一页必须有主图，不能全是文字卡片

这是最重要的实操规则之一。

### 强规则

**每页至少要有 1 个主图形，不允许整页只有文字卡片。**

如果整页只有：

- 几个模块框
- 一堆 bullet
- 若干说明文字

那它更像文案页，不像信息图。

### 常见主图类型

#### 1. 关系图
适合讲“谁和谁什么关系”：

- 象限图
- 分层图
- 飞轮图
- 路线图
- 树状图

#### 2. 机制图
适合讲“它怎么工作”：

- 架构图
- 流程图
- 闭环图
- 数据流图
- 安全隔离图

#### 3. 对比图
适合讲“它和别人有什么不同”：

- 旧 vs 新
- A vs B
- 耦合 vs 解耦
- 自建 vs 托管

#### 4. 证据图
适合讲“这个判断有没有数据支撑”：

- 柱状图
- 折线图
- 比例图
- 关键数字卡

---

## 四、第三步：固定使用“主图 + 辅图 + 小图 + 结论框”结构

这是最稳妥、最适合高管阅读的单页结构。

### 推荐结构

#### 1）主图：讲结构
回答：

**它到底是什么结构？**

例如：

- 三层解耦架构图
- 产品分层关系图
- 平台协同飞轮图

#### 2）辅图：讲差异
回答：

**它和常见做法有什么不同？**

例如：

- 旧方案 vs 新方案
- 自建 vs 托管
- 耦合 vs 解耦

#### 3）小图：讲证据
回答：

**为什么这个判断可信？**

例如：

- 性能数据柱状图
- 安全流程图
- 指标对比图

#### 4）结论框：讲判断
回答：

**这页最终想说什么？**

例如：

- 核心洞察
- 战略启示
- 高管结论

### 为什么有效

因为它天然形成了一个阅读闭环：

- 先看到结构
- 再理解差异
- 然后接受证据
- 最后记住结论

---

## 五、第四步：先区分“通用能力”和“独特性”

这是做产品型信息图时非常关键的一步。

很多厂商都会讲：

- 有状态会话
- 安全沙箱
- 事件日志
- 工具调用
- 多步骤任务

如果图里只写这些，读者会觉得：

**“这不就是又一个 Agent 平台吗？”**

### 正确做法

必须把信息拆成两层。

#### 第一层：行业通用能力
这部分回答：

**“它作为一个平台，基本能干什么？”**

例如：

- 长时执行
- 状态管理
- 工具调用
- 沙箱环境

#### 第二层：公司独特机制
这部分回答：

**“为什么它不是 another platform？”**

例如：

- session / harness / sandbox 三层解耦
- session 独立于 context window
- token 不暴露给 sandbox 的结构性隔离
- 可替换 harness 的长期抽象层设计

### 方法建议

以后做图时，可以强制自己问一句：

**“这一页里，哪些是行业共识，哪些才是这家公司真正独有的机制？”**

只有把这两层分开，图才会显得有洞察。

---

## 六、第五步：名字一定要画面化，不要过度抽象

抽象词通常逻辑对，但不利于扫读。

例如这些词虽然准确，但不够“能看懂”：

- 封装度
- 平台托管性
- 产品完成度
- 架构演进
- 能力抽象层

更好的方式，是用有画面感的名字：

- 运行时提供方式
- 开箱即用程度
- 把大脑和双手拆开
- 零信任凭证隔离
- 从一体化容器到可恢复运行时

### 经验规则

以后给以下元素命名时，都优先用“画面化”表达：

- 坐标轴
- 模块标题
- 分区标题
- 结论标题
- 图注标题

### 命名判断标准

一个名字好不好，可以问自己：

**“读到这个词，脑子里能不能立刻浮现出画面？”**

如果不能，就要继续改。

---

## 七、第六步：文字必须分成三档，不要全在一个层级抢注意力

很多图看起来“字太多”，其实不是因为信息太多，而是因为所有字都在同一个层级上。

### 推荐三层文字结构

#### 第一档：标题级
作用：

**告诉读者这块在讲什么**

例如：

- 核心架构
- 旧方案 vs 新方案
- 零信任凭证隔离
- 核心洞察

#### 第二档：判断级
作用：

**直接告诉读者你想表达的结论**

例如：

- 把运行时从应用逻辑升级为平台能力
- 从一体化容器走向可恢复运行时抽象
- 不是只卖 Agent 能力，而是卖生产级运维承诺

#### 第三档：事实级
作用：

**补充细节、数据、接口名、说明文字**

例如：

- 指标数字
- 小字注释
- API 名称
- 条目说明

### 视觉建议

- 标题级：大字号，强对比
- 判断级：中字号，可重点着色
- 事实级：小字号，减少抢眼程度

---

## 八、第七步：每页信息图建议固定用这套 Prompt 结构

以后做信息图，建议一律按下面 6 段写 Prompt。

### 第一段：画布与风格

写清楚：

- 比例（16:9 / 9:16），默认9:16竖版
- 分辨率（2K）
- 背景（浅底 / 深底）
- 主色（橙、深灰、黑、白等）
- 字体风格（现代中文无衬线）
- 整体气质（研究机构简报 / 顶级咨询公司战略页 / 高级系统设计图）

### 第二段：整图主命题

写清楚：

- 这张图讲什么
- 一句话总结是什么
- 面向谁看（高管 / 产品经理 / 技术负责人 / 开发者）

### 第三段：版式骨架

写清楚：

- 从上到下有几层
- 哪一层是主图
- 哪一层是辅图
- 哪一层是结论区

例如：

- 标题区
- 主图区
- 对比图区
- 数据图区
- 结论区

### 第四段：每个区块的图形类型

不要只写内容，要明确写“这一块应该是什么图”。

例如：

- 主视觉区：三层架构图
- 中部左：旧 vs 新对比图
- 中部右：安全流程图
- 下方：性能柱状图
- 底部：总结框

这是避免“最后生成出来全是卡片”的关键。

### 第五段：每个区块的具体内容

这部分再写：

- 标题
- 小标题
- 文案
- 指标
- 接口名
- 结论句

注意顺序：

**先定图形，再填内容。**

不要一开始就只堆文字。

### 第六段：画面最底部

一行小字：**Data&AI洞察小分队**


### 第七段：负向约束

每次都建议写上：

- 不要 logo
- 不要水印
- 不要卡通风
- 不要复杂 3D
- 不要赛博霓虹
- 不要编号模块
- 不要文字重叠
- 不要错字
- 不要排版过密

---

## 九、第八步：做完以后，只检查这三件事

以后每次出一版图，都用这三个问题复盘。

### 检查 1
**只看版面，不读小字，能不能知道这页的主结论？**

如果不能，说明主图不够强。

### 检查 2
**这页有没有图形上的抓手，还是主要靠文字解释？**

如果主要靠字，说明信息图感不够。

### 检查 3
**这页有没有把“通用能力”和“独特性”分开？**

如果没分开，说明洞察不够尖锐。

---

## 十、建议的常用信息图版式模板

下面是以后最值得反复复用的几种模板。

### 模板 A：战略总览页
适合：

- 产品战略
- 厂商战略
- 平台布局

结构：

- 标题
- 一句话总结
- 三张策略卡
- 产品体系图
- 飞轮图
- 底部洞察

### 模板 B：单产品深描页
适合：

- Managed Agents
- Claude Code
- Databricks 某项能力
- AWS 某个平台能力

结构：

- 标题
- 主图（架构图/机制图）
- 对比图
- 流程图/数据图
- 底部结论框

### 模板 C：竞品对比页
适合：

- Anthropic vs OpenAI
- Bedrock vs Vertex AI
- Claude Code vs Cursor

结构：

- 标题
- 比较维度总览
- 左右对比主表
- 差异解释图
- 底部判断

### 模板 D：机制解释页
适合：

- 某个技术设计
- 某个安全机制
- 某个产品运行逻辑

结构：

- 标题
- 主流程图
- 辅助说明图
- 关键指标
- 结论

## 十一、以后做图前，可直接填写的 5 个问题

以后无论做什么信息图，先写下面 5 行：

### 1. 这页只讲什么主判断？
### 2. 哪个图最能表达这个判断？
### 3. 哪个对比最能拉开差异？
### 4. 哪个数据或流程最能增强可信度？
### 5. 最底部那句收束金句是什么？

只要这 5 个问题写清楚，后面的 Prompt 基本不会跑偏。

---

## 十二、推荐的收束金句写法

一页图最后最好不要只放总结，而要放一句能被记住的话。

### 推荐句式 1
**X 的真正独特性，不在于 A、B、C，而在于 D。**

例如：

- Claude Managed Agents 的真正独特性，不在于也有状态、沙箱和追踪，而在于把 Agent runtime 抽象成 session / harness / sandbox 三层。

### 推荐句式 2
**X 不只是 Y，而是在把 Z。**

例如：

- Anthropic 不只是做几个 AI 产品，而是在把第一方应用实践沉淀为平台能力与生态标准。

### 推荐句式 3
**企业买的不是 A，而是 B。**

例如：

- 企业买的不是 Agent 能力本身，而是可恢复、可追溯、可隔离、可上线的运行时承诺。

---

## 十三、最后的总原则

如果把这份手册压缩成一句话，那就是：

**做信息图，不是把内容“排版漂亮”，而是把观点翻译成图形语言：主图讲结构，辅图讲差异，小图讲证据，底部一句话收束判断。**

## 附录：一份通用 Prompt 骨架

你以后可以直接按下面这份骨架来写：

```text
请生成一张【比例】中文信息图，2K分辨率。

整体风格参考【研究机构简报图 / 顶级咨询公司战略页 / 高级系统设计图】：
【背景、颜色、字体、气质描述】。

主题：
【信息图主题】

一句话总结：
【这页最想表达的主判断】

版式采用【从上到下的层级结构】：
1. 标题区
2. 主图区（明确写是什么图）
3. 辅图区（明确写是什么图）
4. 数据/流程区（明确写是什么图）
5. 结论区

主图区内容：
【写图形类型 + 图中要出现的关键元素】

辅图区内容：
【写对比图/流程图/关系图的具体结构】

数据/流程区内容：
【写指标、柱状图、流程箭头等】

结论区内容：
【核心洞察 + 收束金句】

要求：
- 图形优先，不要全是文字卡片
- 信息层级分明
- 高管可快速扫读
- 中文清晰无错字

负向提示：
【不要 logo、不要水印、不要卡通、不要复杂3D、不要过密排版、不要模块编号】
```
